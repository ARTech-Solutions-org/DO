## Existing caricature implementation

**Why final backgrounds look green.** In `src/prompts.js:59–64` the shared production prompt explicitly asks the model to paint a desaturated green/teal studio background with a warm yellow-green glow. Both server branches send that prompt with the guest image. Although the prompt mentions an attached style reference, neither request attaches a second image. The model returns a complete picture. `src/main.js:554` retains it as `resultSrc` and line 604 assigns it directly to the final image. The export also draws that same image. The green is therefore intended image content in this code path. The color of any particular guest output and the provider used for that session were not measured. No guest images were opened or copied.

## Reuse boundary

- Carry forward the **behavior** of preserving likeness, skin tone, clothing, hair and head coverings, sharing one camera stream across countdown, separating preview mirroring from capture, resizing uploads proportionally, and producing a separately composed download. Reimplement independently unless source reuse rights are confirmed.
- Keep the provider behind a server-side adapter. Replace the green instruction and compare an approved, consented or fictional sample on a flat `#966BFC` background. Plan a reliable subject matte and deterministic purple composite for exact color, then use the same final asset for result and QR. Inspect hair, headwear, clothing edges and background pixels outside the subject. The legacy animation mask has no demonstrated export-quality accuracy.
- Isolate old SVG screens, event branding, reference portraits, welcome footage, print and Electron workflows, example/test data, packages, installers, credentials, R2 account and seven-day link policy. The new event gets independently approved assets, storage and lifecycle settings.
